# «Финни» — данные, формулы и автомат недели

**Версия 1.0 · 23 сентября 2026**

Чего не было ни в одном документе: структуры данных и порядок состояний. Сценарии
глав отвечают за время, тексты и обстановку, `items.md` — за свойства предметов,
этот файл — за то, что хранится и как считается.

**Числа сюда не переносятся.** Цены и пороги живут в `items.md` и в сценариях;
здесь только структуры, формулы и переходы. Одно число в двух местах расходится
за неделю.

ТЗ требует этот документ дважды: пункт 5.4 — структура данных профиля, экономики,
заданий и прогресса; пункт 5.6 — формулы расчёта баланса, наград, состояния и
роста.

---

## 1. Что вообще хранится

Четыре группы. Всё локально, сервера нет, персональных данных нет.

| Группа | Живёт | Сбрасывается |
|---|---|---|
| Профиль | всю игру | при сбросе профиля |
| Прогресс | всю игру | при сбросе профиля |
| Глава | от начала главы до события | при смене главы |
| Неделя | от посылки до итога | при переходе к следующей неделе |

Каталог предметов, ситуации и задания — **не состояние, а контент**. Они лежат
отдельно от кода: ТЗ пункт 2.5.14 требует выноса контента, и `items.md` —
основа для этого файла данных.

## 2. Профиль

| Поле | Тип | Откуда |
|---|---|---|
| `petName` | строка | экран «Создание Финни», вводит ребёнок |
| `silhouette` | 1 из 3 | экран «Создание Финни» |
| `color` | 1 из 3 | экран «Создание Финни» |
| `accessory` | 1 из 3 | экран «Создание Финни» |
| `scale` | `junior` \| `senior` | экран «Выбор масштаба» |
| `introSeen` | флаг | первый запуск проигрывается один раз |
| `soundOn`, `animationOn` | флаги | настройки, требование ТЗ 3.6 |

Три поля внешности дают **девять визуально различимых комбинаций** — строка
минимального объёма ТЗ. Проверяется созданием двух разных профилей, поэтому
комбинация обязана быть видна на главном экране сразу.

Возраст не спрашивается и не хранится. Имя питомца — игровое, не имя ребёнка.

**Масштаб `senior` умножает все денежные величины на 5** и поднимает потолок
фразы до 12 слов. Механика та же, экраны те же.

> **Снято с прототипа, открыто к сдаче.** Умножение на 5 спорит с инвариантом 9
> «любое число на экране не выше 100»: доход становится 150, дорогая цель главы 3
> — 300. Решение 23 сентября: **прототип собирается только на `junior`**, поле
> `scale` пишется константой, экран «Выбор масштаба» в прототип не входит.
> Как жить со старшим профилем дальше — вопрос A7, отвечать до 29 сентября.
> Требование ТЗ про выбор сложности от этого не пропадает.

## 3. Прогресс

| Поле | Тип | Правило |
|---|---|---|
| `chapter` | 1 \| 2 \| 3 | текущая глава |
| `weekInChapter` | 1… | **считается внутри главы, не сквозняком** |
| `marksCare` | целое ≥ 0 | монотонный счётчик, только растёт |
| `marksPlan` | целое ≥ 0 | то же |
| `marksSave` | целое ≥ 0 | то же |
| `inventory` | список id | купленные вещи, мебель и носимое |
| `wallet` `W` | целое ≥ 0 | кошелёк |
| `savings` `S` | целое ≥ 0 | копилка |

**Счётчики никогда не убывают и не обнуляются.** Откат стадии запрещён принципом
безопасной ошибки. Групп три, и они считаются **раздельно**: недостаток заботы не
компенсируется большой суммой накоплений.

Максимум за неделю — по одной отметке каждого типа, то есть три.

### Когда даётся отметка

| Отметка | Условие |
|---|---|
| `marksCare` | всё обязательное недели куплено — **по покупке, а не по касанию миски** |
| `marksPlan` | факт совпал с планом **либо** ребёнок прошёл экран итога и выбрал, с чем идёт дальше |
| `marksSave` | взнос за неделю сделан; считается как частота, а не серия — пропуск ничего не рвёт |

Строка причины на плашке перехода считается по **числу недель, когда действие
было**, а не по длине главы: кормил две недели из трёх — строка говорит «две».
Решение 23 сентября, вопрос D6.

Отметка плана почти автоматическая: пропустить экран итога нельзя. Это принято
осознанно — прямое следствие обещания не наказывать за расхождение. Ворота между
главами держатся на заботе и накоплениях.

Если еда куплена, но ребёнок не коснулся миски, **Финни ест сам при переходе к
итогу**: пропущенный жест — промах по интерфейсу, а не финансовое решение.

## 4. Глава

| Поле | Тип | Правило |
|---|---|---|
| `goalId` | id цели | выбирается **один раз** в начале главы, до первого плана |
| `goalPurchased` | флаг | цель куплена на экране копилки |
| `chapterWantId` | id хотелки | свободная хотелка главы |
| `chapterWantBought` | флаг | в следующую главу не переносится |

Сменить цель внутри главы нельзя: иначе накопление теряет смысл срока.
Невыбранные варианты в этой главе больше не появляются и в следующую не
переносятся.

### Длина главы и переход

| Глава | Длина | Условие конца |
|---|---|---|
| 1 и 2 | 2 недели минимум, 3 максимум | набраны пороги отметок — конец; не набраны — играется третья, после неё конец **в любом случае** |
| 3 | всегда 4 недели | ворот за ней нет, игра кончается новосельем |

Пороги: **во вторую главу при 2 отметках каждого типа, в третью при 4.** При
обычной игре это конец второй и четвёртой недели. Пороги помечены концептом как
требующие проверки на прототипе.

Бесконечного цикла нет ни при каком поведении: игра не длиннее десяти недель.

**Третья неделя главы** играется только при недоборе. Ситуация всегда еда,
задание — по недостающему типу отметок (не хватает двух — по тому, которого
меньше; поровну — по порядку забота, накопления, план), **награды за него нет**.
Ребёнку нигде не сообщается, что неделя дополнительная.

**Событие главы** наступает в конце последней недели независимо от накопленного.
Оба исхода играются, прогресс не обнуляется, следующая цель выбирается сразу.

## 5. Неделя

| Поле | Тип | Правило |
|---|---|---|
| `step` | см. раздел 7 | текущий шаг недели |
| `planNeed`, `planWant`, `planSave` | целые ≥ 0 | заполнены по умолчанию 10 / 10 / 10 |
| `planConfirmed` | флаг | **замораживает план до конца недели** |
| `factNeed`, `factWant`, `factSave` | целые ≥ 0 | считаются по ходу |
| `situationId` | id | ситуация недели, объявляется **до** плана |
| `taskId` | id \| нет | задание недели |
| `taskDone` | флаг | повтор не даёт ни монет, ни отметок, ни предметов |
| `cartItems` | список id | корзина магазина |
| `petFed`, `petWashed`, `petWarm` | флаги | показатели состояния |

### Экран плана

Черновик **допускает превышение**: остаток уходит в минус и показывается,
подтверждение заблокировано, лишнее убирает сам ребёнок. Технический запрет
превышения убил бы компетенцию «расходы не превышают доходов» — тогда действие
совершает приложение.

Ноль разрешён в «Хочу» и в «Нужном» (с мягкой подсказкой «Финни нужно поесть»).

**Ноль разрешён и в «Копилке»**, и подсказки при нём нет — решение 23 сентября,
вопрос A8. Запрет был бы скрытым вердиктом. Подсказка «Финни нужно поесть»
говорит о нужде питомца; подсказка «отложи» говорила бы о правильном поведении
ребёнка, а это запрещено инвариантом 3.

Ввод — счётчик «− N +», шаг одна монета. Ползунки, перетаскивание, проценты и
автоисправление сумм запрещены.

### Взнос

Сумма взноса **решается один раз, на экране плана**. Экран копилки её не
переназначает: кнопка откладывает ровно `planSave`. Под карточкой «Копилка» на
экране плана стоит строка срока, пересчитываемая на каждое нажатие счётчика.

### Из какого направления что списывается

| Покупка | Направление |
|---|---|
| Обязательное недели (еда, мыло, предмет недели) | Нужное |
| Надбавка | **направление базовой покупки**, то есть Нужное **[СЦЕНАРИЙ]** |
| Свободная хотелка главы | Хочу |
| Взнос | Копилка |
| Мячик из задания F5 | только из копилки |

Не хватает в направлении — кнопка «Купить» **не гаснет**. Порядок выходов один
для любой покупки: своё направление → «Хочу» → копилка с отдельным
подтверждением. Окно показывает сумму нехватки и два действия; при снятии из
копилки последствие показывается **до** выбора. Молчаливый перелив запрещён: он
делает план декорацией.

## 6. Формулы

```text
W — кошелёк, S — копилка, I — доход, M — обязательные покупки,
O — необязательные, D — взнос, R — снятия, G — покупка достигнутой цели.

Подтверждение плана:
  planNeed + planWant + planSave <= W        иначе кнопка заблокирована

Доход:
  I = 30, если W < 30
  I = 0,  если W >= 30                        посылка не приходит

Неделя:
  W_конец = W_начало + I − M − O − D + R
  S_конец = S_начало + D − R − G + награда_за_задание

Инварианты:
  W >= 0;  S >= 0;  все суммы — целые монеты
  Осталось_до_цели = max(0, Цена_цели − S)

Срок под карточкой «Копилка»:
  приток_недели = planSave + (10, если на этой неделе есть задание с наградой)
  недель_до_цели = ceil(Осталось_до_цели / приток_недели)
  сравнить с числом недель, оставшихся до события
```

**Награда за задание падает в копилку, а не в кошелёк.** Иначе она ровно на свою
величину уменьшала бы следующую посылку — приложение выдавало бы монеты и молча
забирало обратно.

**Покупка достигнутой цели** не вычитается повторно из кошелька и не отменяет
отметку взноса за эту неделю. При закрытой цели взнос больше не предлагается,
освободившиеся монеты остаются в кошельке.

> **Открыто.** Что делать с переплатой, когда награда за задание переносит копилку
> через цену цели: на каноническом пути главы 1 при дешёвой цели в копилке
> оказывается на 10 монет больше нужного. Переносить в следующую главу, срезать
> или не давать взнос сверх нужного — не решено. См. `open-questions.md`, A5.

## 7. Автомат недели

Шаги. Порядок свободный, **кроме одного: до подтверждения плана тратить нельзя.**

```
  Посылка ──▶ Объявление ситуации ──▶ План ──[подтверждён]──┐
                                                            │
        ┌───────────────────────────────────────────────────┘
        ▼
  { Магазин · Ситуация · Забота дома · Хотелка · Копилка }   порядок любой
        │
        ▼
     Итог недели ──▶ [последняя неделя главы] ──▶ Событие ──▶ смена главы
        │
        └──▶ Свободная игра ──▶ «Следующая неделя»
```

| Шаг | Что происходит | Деньги |
|---|---|---|
| Посылка | приходит доход, если `W < 30` | `W += I` |
| Объявление | ситуация недели названа **до** плана | — |
| План | три счётчика, строка срока, подтверждение | замораживает план |
| Магазин | **единственное место, где уходят деньги** | списание в корзине |
| Ситуация | выбор базового варианта и надбавки | оплата в корзине |
| Забота дома | касание миски кормит, мыла — моет | **денег не трогает** |
| Хотелка | доступна в магазине всю главу | `W -=` цена |
| Копилка | кнопка откладывает ровно `planSave` | `W -= D`, `S += D` |
| Итог | три факта, два действия | — |
| Событие | только в последнюю неделю главы | покупка цели из `S` |

**Корзина и есть подтверждение покупки.** Отдельного модального окна нет: корзина
показывает список с ценами и метками направлений, сумму и кнопку «Купить».
Модальных окон в игре ровно два, оба обязательны: нехватка в направлении и снятие
из копилки.

### Два действия на экране итога

| Действие | Что делает |
|---|---|
| «Оставить план» | следующая неделя открывается с 10 / 10 / 10 |
| «Взять как вышло» | открывается с фактическими числами этой недели |

Ни одно не помечено рекомендуемым. Дефолт следующего плана — результат этого
выбора, а не константа.

### Свободная игра

Доступна после итога, до нажатия «Следующая неделя»: играть можно уже купленным.
**Ни монет, ни отметок, ни предметов она не даёт** — иначе повторные заходы
накручивали бы экономику.

## 8. Контент как данные

Выносится из кода отдельными файлами — требование ТЗ 2.5.14.

| Набор | Ключевые поля | Источник |
|---|---|---|
| Каталог | `id`, название, категория, цена, тип, иконка влияния, где и когда продаётся | `items.md` §2, §3а, §5, §7 |
| Цели | `id`, название, цена, тип, куда попадает, глава | `items.md` §3 |
| Ситуации | неделя, базовая позиция, надбавка, тексты объявления | сценарии глав |
| Задания | `id`, шаблон, экран, награда, тексты | сценарии глав |
| Обстановка | `id`, место в комнате, роль | `items.md` §4 |

**Пять типов предметов, больше не бывает:** расходник (использован и исчез),
вещь (остаётся навсегда), носимое (слой на Финни), мебель (меняет комнату),
обстановка (не покупается).

**Правило долговременной вещи:** куплена один раз — больше не продаётся и в списке
не появляется, и это **не объясняется словами**. Никаких подписей «у вас уже
есть». Исключение одно — задание F3 «Куртка уже есть», где это и есть предмет
обучения.

## 9. Что проверять на границах

Места, где реализация ломается тихо.

- Подтверждение плана при `planNeed + planWant + planSave > W` — заблокировано,
  но ввод разрешён и минус показан.
- Покупка при нехватке в направлении — кнопка не гаснет, открывается окно.
- Снятие из копилки — отдельное подтверждение, последствие показано до выбора.
- Дубликат вещи в корзине не списывается.
- Посылка при `W >= 30` не приходит, и это не сообщается как ошибка.
- Задание пройдено повторно — ни монет, ни отметок, ни предметов.
- Еда куплена, миска не тронута — Финни ест сам при переходе к итогу.
- Цель закрыта досрочно — взнос больше не предлагается.
- Отрицательных `W` и `S` не бывает ни в одном сценарии.

Полный набор проверок — `test-cases.md`.
