# С чего начинать

Документов много. Читать их подряд не надо — порядок зависит от того, что ты
делаешь.

## Первый раз в проекте

1. `../../CLAUDE.md` — правила, инварианты, чего в продукте нет. **Обязательно.**
2. `build-plan.md` — что именно собираем и в каком порядке.
3. `data-model.md` — структуры, формулы, автомат недели.
4. `screen-map.md` — экраны и переходы.

Четыре файла, полчаса. Этого достаточно, чтобы начать.

## Дальше — по задаче

| Делаешь | Читаешь |
|---|---|
| экран или шаг недели | `scenario-chapter-1.md`, нужный шаг целиком |
| что-то с предметом, ценой, категорией | `items.md` |
| вёрстку, цвет, шрифт, компонент | `style-guide.md` |
| анимацию | `animation-howto.md` |
| проверку доступности | `ui-constraints.md` |
| прогон перед показом | `test-cases.md` |
| главы 2 и 3 | `scenario-chapter-2.md`, `scenario-chapter-3.md` |

## Когда что-то не сходится

`open-questions.md` — реестр нерешённого. Сначала загляни туда: скорее всего,
вопрос уже задан и ждёт ответа Эмиля.

Нет его там — **допиши, а не решай сам**. Молча выбранный дефолт вскроется на
детях.

## Откуда всё взялось

`../source/` — первоисточники. Нужны, когда надо проверить, откуда взялось
решение, а не чтобы реализовывать по ним.

| Файл | Что это |
|---|---|
| `tz.md` | техническое задание заказчика |
| `concept.md` | концепт «Финни» от 17 сентября |
| `customer-answers.md` | что заказчик уточнил устно и в чате |

**При расхождении источника с документами этой папки прав документ этой папки:**
он новее и учитывает решения 21–23 сентября.

## Что чем является

| Метка | Значит |
|---|---|
| **[ТЗ]** | требование заказчика, менять нельзя |
| **[КОНЦЕПТ]** | решение концепта |
| **[ГАЙД]** | правило из `style-guide.md` |
| **[ПРОД]** | продуктовое обоснование |
| **[СЦЕНАРИЙ]** | сценарист решил за команду, **ждёт подтверждения** |

`[СЦЕНАРИЙ]` — единственная метка, которую можно оспорить. Остальные четыре
означают, что решение уже принято и переигрывать его в коде не надо.
