# Архитектура

«Финни» — одно Android-приложение без сервера. Два модуля Gradle: правила игры отдельно
от интерфейса.

| Модуль | Что внутри | Зависит от |
|---|---|---|
| `core` | модель состояния, правила недели, расчёты, тексты из состояния, демо-путь; чистый Kotlin/JVM | kotlinx.serialization |
| `core/src/main/resources/content/` | контент игры данными: предметы и цели, главы и недели, задания, все тексты | — |
| `app` | интерфейс на Jetpack Compose, хранение состояния, питомец и анимации | `core`, AndroidX |
| `art/app` | готовая графика: PNG-слои Финни, предметы, комнаты; в сборке — корень ассетов | — |

## Поток данных

```
 касание  ──▶  экран (app/ui/screens)  ──▶  AppModel.act { game.ход(состояние) }
                                                  │
                                    Game (core): новое состояние или IllegalMove
                                                  │
                    GameStore: запись state.json ◀┘ ──▶ StateFlow ──▶ Compose перерисовывает экран
```

- **Экраны ничего не считают.** Любая цифра на экране — ответ `Game` или `Explain` из `core`:
  сколько осталось в «Нужном», хватит ли к событию, что написать на итоге.
- **Ход — чистая функция** `(GameState) -> GameState`. Запрещённый ход бросает `IllegalMove`,
  интерфейс его просто не применяет (и такие ходы не предлагает).
- **Сохранение после каждого хода.** `GameStore` пишет JSON во внутреннюю память через временный
  файл: обрыв посреди записи не портит сохранение. Закрыть приложение посреди недели и открыть —
  всё на месте (ТЗ 2.5.13).

## Модель состояния

`GameState` (`core/model/State.kt`) — всё, что хранится:

| Группа | Что | Живёт |
|---|---|---|
| `Profile` | имя питомца, окрас, аксессуар, сложность, анимации | всю игру |
| `Progress` | глава, неделя в главе, три счётчика отметок, кошелёк, копилка, вещи, пройденные задания, история недель | всю игру |
| `ChapterState` | цель главы, куплена ли хотелка, недели с действием для строки причины | главу |
| `WeekState` | посылка, план, факт по направлениям, взнос, покупки, выбор ситуации, задание, бонус | неделю |
| `Phase` | где игра: знакомство, неделя, после итога, событие, переход главы, конец игры, свободная игра | — |

Структура полей и формулы — [`data-and-formulas.md`](data-and-formulas.md).

## Автомат недели и главы

```
 Посылка ─▶ Объявление ─▶ План ─[подтверждён]─▶ { Ситуация · Магазин · Забота · Копилка · F6 } ─▶ Итог
                                                                                               │
          ┌──────────────── «Следующая неделя» ◀── свободная игра ◀── глава не кончилась ◀─────┤
          │                                                                                    ▼
          │                                                   глава кончилась ─▶ Событие главы
          │                                                                          │
          └── выбор цели ◀── плашка перехода со строкой причины ◀── главы 1, 2 ─────┤
                                                                                      └── глава 3 ─▶ Конец игры
```

- До подтверждения плана тратить нельзя: магазин — витрина, взнос не предлагается (инвариант 6).
- Шаг недели на записке дома считает `Game.nextStep`: посылка → план → магазин → забота →
  копилка → (F6) → итог → следующая неделя.
- **Глава кончается по отметкам**: главы 1 и 2 — от двух до трёх недель, в следующую главу при 2 и
  4 отметках каждого типа; не набрано за две недели — третья, запасная, и после неё конец в любом
  случае. Глава 3 — всегда четыре недели. Игра не длиннее десяти недель ни при каком поведении.

## Контент данными (ТЗ 2.5.14)

| Файл | Что | Как добавить |
|---|---|---|
| `items.json` | предметы: цена, категория, тип, значок влияния, надбавка к чему; цели глав | строка в `items`, картинка `art/app/item_<id>.png` |
| `chapterN.json` | глава: комната, доход, цели, хотелка, длина, пороги; недели с объявлением, полками и заданием | неделя — объект в `weeks`; глава — новый файл `chapter4.json` |
| `tasks.json` | задания: шаблон, награда, предмет, тема ТЗ 2.5.8 | строка на готовый шаблон |
| `texts.ru.json` | все тексты игры; ключи, формы слова «монета» | строка; проверку нормы делает `TextLintTest` |

**Как добавить задание без переделки логики.** Шаблоны заданий — `shop` (купить на неделю),
`choice` (выбор на копилке), `plan` (сколько отложить), `duplicate` (вещь уже есть), `pay` (чем
заплатить), `sort` (разложить траты). Новое задание — строка в `tasks.json` с одним из шаблонов и
`taskId` у нужной недели в `chapterN.json`; тексты — в `texts.ru.json`. Код не меняется.

## Интерфейс

| Пакет | Что |
|---|---|
| `ui/Navigation.kt` | экраны и переходы: глубина два уровня от дома, «назад» всегда ведёт домой |
| `ui/screens/` | дом, план, магазин, ситуация, копилка, F6, итог, событие, конец игры, дневник, раздел взрослого, первый запуск |
| `ui/components/` | комната, плашки, банки, корзина, ценники, клетки копилки, вход для взрослого |
| `ui/pet/FinniRig.kt` | риг Финни: шесть поворотных частей из PNG, реакции, носимое, поза лёжа |
| `ui/art/` | загрузка PNG из ассетов, обрезка по непрозрачному, точки поворота |
| `data/GameStore.kt` | состояние в JSON, отложенная игра ребёнка на время демо, удаление данных |

## Хранение

Один файл `state.json` во внутренней памяти приложения (`Context.filesDir`). На время демо игра
ребёнка лежит рядом в `child.json` и возвращается кнопкой. Сервера, аккаунтов, сети и разрешений
нет. Подробно — [`privacy.md`](privacy.md).

## Демо-режим

`core/engine/Demo.kt`: готовый питомец и начало любой из восьми недель канонического пути.
Состояние недели не записано числами, а получается прогоном канонических ходов через тот же
`Game` — если правило поменяется, демо поменяется вместе с ним. Вход — раздел для взрослого.
